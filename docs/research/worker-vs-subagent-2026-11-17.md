## 6. 깨지는 것

- **증거 · 리뷰 기록의 주체(결정 162).** `recorderRefusal` 은 "기록하는 세션의 checkout 이 PR head 를 쥐면 작성자" 로 본다. MCP tool 셋(`review_record` · `evidence_record` · `stage_record`)은 MCP 서버의 `process.cwd()` 를 그 checkout 으로 넘긴다. 서브에이전트의 MCP 호출은 주인의 서버로 가고, 그 cwd 는 주인의 worktree 다. 그래서 PR 을 쓴 서브에이전트가 MCP 로 자기 증거를 기록해도 막히지 않는다. CLI 길(`agentCheckout`)은 Bash 의 cwd 를 읽으므로 자기 worktree 에서 부르면 막힌다. 둘 다 코드에서 읽었고, 돌려 보지는 않았다. worker 서브에이전트 정의에서 `evidence_record` · `review_record` · `stage_record` · `land` 를 빼고, 게이트가 `call.subagent` 일 때 그 tool 을 거부해야 한다. 기록은 주인이 한다(비서 노트와 같다).
- **`start_unit` · lineage · 깊이.** 서브에이전트에는 Task · Dispatch · `unit_started` 가 없다. 주인이 항목에 단계 시작과 끝(서브에이전트 id, worktree, branch, head, 다음 할 일)을 남기는 행이 필요하다. 깊이는 Orca 의 nesting 상한 대신 Claude Code 의 `spawnDepth` 를 따른다. 2는 보였고 3은 본 적이 없다. 그래서 worker 서브에이전트가 리뷰어를 한 단 더 띄울 수는 있지만 그 아래는 기대하지 않는다.
- **`worker_done` · `merge_ready` · `[gate:self-land]` · READY-WAIT.** 모두 Dispatch 에 묶여 있다. 단계의 끝은 서브에이전트의 보고이고, merge_ready 는 주인이 `land` 를 부르는 것으로 바뀐다.
- **패널 · brief 의 worker 행.** Orca Dispatch 에서 읽는다. 서브에이전트는 보이지 않는다. 오너는 필요하지 않다고 했다(보기 좋게 하는 mod 는 LATER). brief 는 항목의 단계 행에서 읽게 바꾼다.
- **REAPER.** isolation: worktree 의 worktree 는 Claude Code 가 만들고 바뀐 것이 없으면 지운다. REAPER 가 모르는 checkout · branch 가 생기므로 주인이 `resource_record` 로 남긴다. compose 같은 오래 사는 자원은 예외 (b) 로 세션에 둔다.
- **pressure · capacity.** 살아 있는 Dispatch 를 센다. 서브에이전트는 세지 않는다. 오늘 서브에이전트가 동시에 몇 개 돌았는지는 재지 않았다.
- **hook 의 역할 판정.** 게이트는 `agent_type` 과 첫 프롬프트로 역할을 읽고 `agent_id` 로 서브에이전트 호출을 가른다. hook 입력의 transcript 와 터미널은 주인 세션의 것이라, worker 서브에이전트의 호출은 주인의 Task · Run 사실을 물려받을 것이다(코드에서 읽었고, 돌려 보지는 않았다). worker 역할 게이트를 서브에이전트의 `agent_type` 으로 다시 걸어야 한다.
- **권한 프롬프트.** 서브에이전트는 프롬프트를 띄우지 못한다. 오늘 워커 둘이 작업 폴더 밖 읽기 프롬프트에 멈췄다. 정의에 "임시 · compose · outbox 파일은 자기 worktree 안에만" 을 적고, 오너가 봐야 하는 프롬프트는 예외 (c) 로 둔다.
- **advisor 예산(결정 200).** 세션 transcript 에서 단위마다 센다. 서브에이전트 transcript 는 따로 있고, 서브에이전트가 advisor 를 쓰는지는 확인하지 못했다.

## 7. 옮기는 길과 되돌리는 길

1. **S0 (지금).** 결정 325 로 숫자와 추천만 남긴다. 비서 정의(결정 324)는 그대로 간다. 비서와 worker 서브에이전트의 경계는 이렇다. 비서는 repo 를 고치지 않고 읽기 · 확인 · 답 · 기록 초안을 맡는다. worker 서브에이전트는 항목 하나의 코드 · 커밋 · PR 을 자기 worktree 에서 맡고 Slack · Jira 와 sangsoe 기록 tool 은 쓰지 않는다. 기록은 둘 다 주인의 것이다.
2. **S1.** `sangsoe:worker` 서브에이전트 정의를 더하고(isolation: worktree, 기록 tool 없음, 짧은 보고 꼴), 6절의 기록 주체 게이트를 함께 넣는다. 리드는 worker · docs · sweep 종류(오늘 13개, 5–15분)에만 쓰고, hard · design 은 세션으로 둔다. 같은 스크립트로 2절의 칸을 다시 잰다.
3. **S2.** pr-monitor 가 CI 끝 · 리뷰 제출 · 승인 이벤트를 항목의 리드 Run 으로 깨우게 하고, 깨어난 리드가 "이 PR 이어 가기" 단계를 새로 띄운다. 항목에 branch · PR · head · 다음 할 일을 남긴다.
4. **S3.** hard · design 으로 넓힌다. 독립 세션은 예외 (a)(b)(c) 에만 남긴다.

되돌리는 길: 단계마다 `start_unit` 의 워커 세션 길을 지우지 않고 둔다. 리드가 어느 쪽으로 띄울지가 스위치이고, store 에서 지우는 행이나 스키마는 없다. 그래서 어느 단계에서든 리드가 다시 `start_unit` 을 부르면 지금으로 돌아간다.
