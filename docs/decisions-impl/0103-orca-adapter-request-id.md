# 103. Orca 어댑터는 요청 id 를 만들지 않고 Orca 가 알려 준 것을 쓰며, 소비하는 메일 읽기는 감싸지 않는다

결정 60 을 구체화한다(바꾸지 않는다). 결정 60 은 "변경 호출은 요청 id 를 달고 응답을 잃으면 `request-show` 뒤에만 다시 보낸다"고 한다. Orca 1.4.250 의 명령 스키마(`orca agent-context --json`)는 `--retry-request` 를 "모르는 결과 뒤의 정확한 복구에만" 쓰고, 그 id 는 Orca 가 알려 주며 호출한 터미널에 묶인다고 적는다. 그래서 어댑터는 첫 호출에 id 를 만들지 않는다. 쓰기 결과의 JSON 에서 `requestId` 꼴의 키를, 없으면 stderr 의 `--retry-request <id>` 를 찾아 결과에 싣는다. 응답을 잃은 쓰기(`response_lost`)는 `recoverWrite` 가 `request-show` 를 먼저 읽고, `completed`·`pending` 일 때만 같은 id 로 다시 보낸다. `absent` 는 "아무 일도 없었다"는 증거가 아니라서 다시 보내지 않고 부른 쪽에 돌려준다.

미확인: 첫 쓰기에서 Orca 가 id 를 어느 칸에 싣는지. 녹화 중에는 Orca 에 쓰지 않았으므로 두 자리를 다 본다. 첫 실제 쓰기를 하는 단위(결정 루프·시작 절차)가 확인하고 찾는 자리를 좁힌다.

설계 2절 첫째 칸 표의 메시지 행에는 `check` 가 있지만 그것은 세션 자신의 동사다. 코어의 어댑터에는 소비하는 메일 읽기 래퍼가 없고 메일은 `inbox` 로 읽는다. 대체 시작 대기(`terminal wait --for tui-idle`)는 표에 있으므로 래퍼를 두되, 그것을 쓰던 대체 시작은 오너 d125 로 없어졌다. 쓰는 곳이 없으면 결정 94 를 접을 때 함께 지운다.
