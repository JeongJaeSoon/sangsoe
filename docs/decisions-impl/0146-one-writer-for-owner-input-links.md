# 146. 오너 입력 연결과 대기 풀기의 규칙은 `core/owner` 한 곳에 둔다

결정 91 의 입력 연결 · 대기 풀기를 쓰는 곳이 둘이었다. U13 의 hook(`core/session/shell.ts` · `record.ts`, 구현 결정 131)이 자기 규칙으로 `evidence{owner_act:*}` · `owner_act_unlinked` · `waiting_released` 를 직접 썼고, U14 의 `core/owner/link.ts` · `release.ts`(구현 결정 134 · 135)는 리뷰를 거친 규칙을 가졌지만 부르는 곳이 없었다. 오너의 규칙("데이터 저장은 2중이 되지 않아야")에 맞춰 하나로 모은다.

- **부르는 길.** `!` 줄: hook → `recordShellInputs`(transcript 읽기 · 마스킹한 `owner_action` 행) → `ShellLine` → `core/owner` 의 `linkShell` → `recordShellLink`. 대기: Stop · PostToolUse · SessionEnd hook → 신호(`turn_ended` · `tool` · `session_ended`) → `recordReleases`. `core/session` 에는 감시 목록 · 짝짓기 · 대기 풀기 규칙이 남지 않는다(`test/session/one-writer.test.ts` 가 grep 으로 고정한다).
- **지운 U13 규칙과 그 결함.** 시각을 문자열로 비교했다(`+01:00` 처럼 오프셋이 다른 시각이 순서를 틀린다). stdout 의 아무 URL 이나 `seen` 으로 이었다. 저장소를 보지 않았다. 감시 목록을 `startsWith` 로 맞춰 `gh releases` 가 `gh release` 로 잡혔다. `core/owner` 쪽은 `Date.parse` 비교(가), 저장소 확인, PR URL 연결, 종료 코드가 없으면 `run_ok` 의 그 저장소 run URL 만, 둘 이상 맞으면 `unlinked`, 설정의 감시 목록을 단어 단위로 맞춘다.
- **키 형식은 `core/owner` 의 것.** `evidence:owner_act:<uuid>` 와 `owner_act_unlinked:owner_act:<uuid>`. 설계의 `owner_act:<uuid>` 를 type 접두어 뒤에 그대로 두는 꼴이라 `evidence:probe:<task>:<kind>` 와 같은 "type:종류:대상" 순서가 된다. U13 이 쓴 `evidence:<uuid>:owner_act` · `owner_act_unlinked:<uuid>` 행은 지우거나 옮기지 않는다. 읽는 쪽은 키가 아니라 type 과 payload 로 읽고, hook 은 `owner_action:<session>:<uuid>` 가 이미 있는 줄을 다시 잇지 않으므로 한 줄이 두 형식을 갖지 않는다(시험 "rows the U13 hook wrote under the old keys…").
- **Orca 를 읽는다.** `linkShell` 은 항목의 상태(🟢 인 오너 항목만)를 본다. 그래서 새 `!` 줄이 있을 때만 hook 이 Orca 스냅샷(run-current · 이름 붙은 Run 마다 task-list · gate-list)을 한 번 읽고 `itemFacts` 를 접는다. Orca 가 답하지 않으면 그 줄들의 `owner_action` 도 쓰지 않고 돌아간다. 다음 hook 이 같은 줄을 다시 읽어 잇는다. `owner_action` 만 먼저 쓰면 그 키가 다음 시도를 막아 연결이 영영 빠지기 때문이다.
- **마스킹(결정 34).** `recordShellLink` 가 `observed` 와 `act` 를 쓸 때 마스킹한다. `linkShell` 에 넘기는 명령은 마스킹하지 않는다. 짝짓기는 원문 토큰으로 해야 하고, 저장되는 것은 마스킹한 글뿐이다.
- **줄의 저장소.** hook 은 세션 저장소를 읽지 않는다(`repo: null`). 그래서 `-R`/`--repo` 가 있으면 그것, 없으면 명령 안의 GitHub URL(`gh pr merge https://github.com/<o>/<r>/pull/N`)의 저장소를 쓴다. 둘 다 없으면 저장소를 이름 대는 항목에는 잇지 않는다(감시 명령이면 `unlinked`).
- **대기 풀기 근거 문자열.** PostToolUse 의 근거가 `post_tool_use:<tool>` 에서 `core/owner` 의 `tool:<tool>` 로 바뀐다. `source` 는 hook 이름(`Stop` · `PostToolUse` · `SessionEnd`)이다. 행은 대기 행의 entity 를 이어받아 항목 시간순에 남는다.
