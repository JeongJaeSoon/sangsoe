# 136. 패널의 코어 입구와 버튼(U19)

- **입구 하나.** 패널이 부르는 코어는 `core/brief/panel.ts` 의 `PanelCore` 하나다: `brief(target)` · `statusBar()` · `act(a)`. worker 는 `orca-plugin/core-link.ts` 로 실행 시점에 코어를 찾아(`../dist/core/index.js` → `../core/index.ts`, U15 의 monitor 와 같은 길, 결정 132) `openPanelCore()` 를 열고, 패널 요청을 그대로 넘기고 답을 그대로 돌려준다. worker 는 세지도 쓰지도 않는다. 정적 import 는 폴더 밖으로 나가지 않는다(승인과 내용 해시가 폴더만 덮는다).
- **요청과 응답.** `panel.brief {group?, item?}` → `{ok, value: {model: BriefModel, todo: OwnerTodoRow[]}}`. `panel.act` 는 셋만 받는다: `{kind:"answer", decision:"dNNN", choice:"recommended"}` · `{kind:"answer", decision, text}` · `{kind:"done", item:"iNNN"}`. 그 밖은 코어에 닿기 전에 `bad_input` 으로 거부한다. 거부는 코어와 같은 `{code, reason, fix}` 다.
- **행 ID.** 패널의 `<tr data-id>` 는 `BriefModel` 의 `Row.id` 그대로다(dNNN · iNNN · `lead:<묶음>` · `act:<…>` · `seq:<n>`). 행에 `kind` 가 없으므로 버튼은 같은 응답의 `owner_todo` 행의 `kind` 로 고른다. 내려가기는 `lead:` 행 → `{group}`, 항목 행 → `{item}` 이고 뒤로는 쌓은 목록을 하나 뺀다.
- **결정 버튼.** "추천대로 답" 은 패널이 보낸 글이 아니라 코어가 같은 모델의 추천 칸을 다시 읽어 답으로 쓴다(추천이 `—` 이면 `no_recommendation`). "다른 답" 은 그 행 아래 입력 칸의 글을 보낸다. 둘 다 `owner_action{origin: button, source: plugin:panel}` 을 먼저 쓰고 그 seq 로 `decisionAnswer`(CLI·MCP 와 같은 함수)를 `linkedBy: "button"` 으로 부른다.
- **패널은 Run 을 쥐지 않는다.** worker 는 세션이 아니라 `run-current` 가 없다. 그래서 `decisionAnswerFrom`(입구가 `run-current` 를 읽는다) 대신 `decisionAnswer` 를 `callerRun: ""` 로 부른다. 열린 게이트는 여기서 풀지 않고, 게이트를 쥔 Run 에 `handoff` 한 통으로 넘긴다(결정 77 라, 다른 Run 의 답과 같은 길). 답은 기록되고 결정은 닫히며, 게이트는 그 Run 이 같은 호출로 푼다.
- **완료 버튼.** 🟢 오너 항목(`owner_todo.kind = owner_item`) 행에만 단다. 부르는 함수는 U14 의 `ownerDone(ports, input, facts, {task, session?})` 이고 같은 꼴의 포트(`OwnerDoneFn`)로 받는다. U14 가 이 base 에 없을 때는 `not_available` 로 거부하고 아무것도 쓰지 않는다. U14 가 들어오면 `openPanelCore` 에 그 함수를 넘기는 한 줄이다.
- **버튼을 달지 않는 행.** `waiting_human` 행(터미널의 권한 대기)과 `undelivered_answer` 행은 버튼이 없다. sangsoe plugin 에는 `terminal:send` 능력이 없어 권한 프롬프트에 답할 수 없고, 버튼으로 `waiting_released` 를 쓰면 터미널은 아직 기다리는데 할 일에서 빠진다(결정 91①: 풀림은 관측한 재개 또는 그 대기에 정확히 이어진 버튼). 전달 안 된 답은 시작 절차와 `notified` 키가 다시 싣는다(결정 91④).
- **상태 표시줄 B.** `statusBarItem(o: Overview) → {text, tone, tooltip}`. 글은 `🚧${summary.blocked} · 결정${todo.decisions} · 🔄${summary.doing}`(결정 92⑤ 의 꼴, 64자 이하), `todo.total > 0` 이면 `danger` 아니면 `neutral`. worker 는 30초 라운드마다 이것을 `statusBar.update` 로 보낸다. 코어를 못 읽으면 숫자를 짐작하지 않고 `sangsoe ?` 를 보인다.
- **매니페스트.** 패널 id `probe` → `brief`, entry `panel/probe.ts` → `panel/index.ts`. 기여가 바뀌어 승인 지문이 바뀌므로 다음 릴리스는 새 리뷰 기록과 `sangsoe plugin approve` 가 필요하다.
