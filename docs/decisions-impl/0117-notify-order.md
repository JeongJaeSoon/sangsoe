# 117. `notify` 가 지키는 받는 순서와 한 번

결정 76(5)·80 N8 과 부록 `#delivery` 를 함수 하나로 옮기며 정한 것이다.

- **입력은 id 만.** 부르는 쪽은 받는 사람들(`dispatch` = 일을 쥔 워커, `leadRun` = 소유 리드의 Run, `orchestratorRun`)과 보낼 사람(`to`)을 준다. 주소는 `notify` 가 `dispatch:<id>`·`run:<id>` 로 만든다. `term_` 로 시작하는 id, `:`·공백이 든 값(이미 만든 주소)은 거부한다.
- **순서.** 받는 사람 셋 가운데 주어진 사람만 순서에 든다(없거나 죽은 사람은 부르는 쪽이 빼고 준다). 맨 앞 사람에게는 언제든 보낸다. 그 뒤 사람에게는 바로 앞 사람이 같은 조건의 `notified` 를 이미 받았을 때만 보낸다. 아니면 `out_of_order` 로 거부한다. 오너는 순서에 없다.
- **한 번.** 보내기 전에 같은 키의 `notified` 를 찾고 있으면 보내지 않는다. 보낸 뒤 `notified` 를 쓴다. 보내기는 됐는데 줄을 쓰기 전에 죽으면 다음 호출이 한 번 더 보낼 수 있다(적어도 한 번). Orca `send` 의 요청 id 로 이를 막는 길(결정 60)은 영수증 모양이 기록되지 않아 아직 쓰지 않는다.
- **`msg_id`.** `send` 영수증에서 메시지 id 를 찾고, 없으면 요청 id, 그것도 없으면 `unrecorded` 를 적는다. 영수증 모양은 아직 실측되지 않았다.
- **모아 보내기(부록 `#delivery`, 기본 300초)는 이번에 만들지 않았다.** 결정 루프의 보내기는 모두 즉시 깨움 쪽(답·막힘 해제)이다.
