# 102. Node 하한을 24.15 로 올린다: 번들 SQLite 가 결정 35 의 하한을 넘는 첫 24.x 이다

결정 96 의 Node 하한(24.2)을 바꾼다. 코어는 `node:sqlite` 가 번들한 SQLite 를 쓰는데, Node 저장소의 `deps/sqlite/sqlite3.h` 를 태그마다 읽으면 24.2.0 은 3.50.0, 24.12.0 은 3.50.4, 24.13.1·24.14.x 는 3.51.2, 24.15.0 이 처음으로 3.51.3 이다. 결정 35 의 하한(3.51.3 이상, 3.50 계열은 3.50.7 이상, 3.44 계열은 3.44.6 이상)에 못 미치는 런타임에서 시작 점검은 DB 를 열지 않으므로, 하한을 그대로 두면 선언한 최소 버전에서 sangsoe 가 돌지 않는다.

그래서 `package.json` 의 `engines.node` 를 `>=24.15` 로, CI `unit` 작업의 `node-version` 을 `24.15.0` 으로 올린다. 시작 점검은 느슨하게 하지 않는다(split Q2). 시험은 실제 런타임의 SQLite 가 하한을 넘는지를 직접 확인한다.

대안: 하한을 24.2 로 두고 시험만 버전 탐침을 주입한다. 버렸다: CI 가 최소 버전에서 실제 DB 를 한 번도 열지 못하고, 사용자는 선언된 최소 버전에서 거부를 만난다. 영향: Homebrew formula(U4)는 Node 24.15 이상을 요구해야 한다.
