## Unreleased

- **A long prompt driven into a terminal is no longer stored as the owner's, and neither is a subagent's hand-back (282).** The release smoke on 0.1.10 drove short lines and long prompts into a session. The short lines left no `owner_action`, as 280 intends; the long ones did, and one released a wait as the owner. Claude Code 2.1.325 hands a long text that arrives at once to the hook inside a `<pasted_content id="…">` block, so its hash differed from the one the plugin had recorded for the text Orca reported. A block that wraps the whole prompt is now removed before the text is hashed and classified; text around a block is still the owner's. A prompt that starts with the `<agent-message` tag, which is how a subagent's result reaches the session, is classed with Orca's own lines. Not measured on a real Orca yet: the 0.1.11 release smoke drives a long prompt again.
- **A merged PR closes a Task its worker reported failed, the brief says why such a row is blocked, and a worker on a repository without CI ends with a wait line (283).** In the smoke the worker's `land` was refused with `checks_missing` (the smoke repository has no CI), the worker reported failed, and the orchestrator merged the head as decision 226 says. The merge was recorded, but the Task stayed failed, the Run's session got no line, and the brief row showed 🚧 with no PR, no reason and nobody it waits on. `closeMerged` now treats a failed Task whose result is not a cancellation like an open one. The brief row of a failed Task waits on the lead and gives the first line of the worker's report. Once the PR is merged the row says what the close will do: what still keeps the Task (another PR of the item still open, for one), or that the next prompt of the Run's session closes it if its worker has ended. `deliver-ticket` tells a worker in that spot to end with `READY-WAIT: checks_missing` instead of failed. Not measured: whether Orca takes `task-update --status completed` on a failed Task; if it does not, the row keeps saying the PR is merged.
- **The item a resolved gate was holding is counted in the same line (284).** The Run's session resolved a closed decision's gate and printed a count that was read before the resolve, so the freed item came one prompt later. After resolving a gate the hook reads `task-list` once more and counts from that.
- **The start note under the PC 부하 rows sits where the lines begin and reads `HH:MM부터 기록` (285).** On the real panel the lines began mid-column in the 24-hour span while the note stood at the column's left edge, next to the load line under it. The note now starts at the lines' first point, or ends there past the middle, with 8px before the line under it. This changes a place the owner had confirmed on the fixture screen (281 ③). Measured in headless Chrome only; the real panel is for the next release smoke. Also recorded, with nothing changed: the panel's controls do not answer an accessibility press in Orca, so smoke steps click by coordinates.
- **The orchestrator may run read-only Orca lookups and send a body file, and the refusal names a form Orca takes (286).** `[gate:delegate]` refused `orca repo list | head`, a skill guide piped through `grep`, and a `send` whose body was `"$(cat brief.md)"`, and its hint named `--body-file`, which Orca's `send` does not have. It now lets `repo list|show`, `status`, `worktree current`, `--help` and `--version` through, treats `grep` like `head`, and lets `cat` read the file types the Read tool would. `--help` under Orca's `claude-teams` and `agent-teams-tmux` shims is not let through: they pass their arguments on. The hint says to write the `.md` with the Write tool and send it as `--body "$(cat <file>.md)"`. The gate is not a guard against shell writes: `mkdir` and a `cat` with no file are refused as before, but it does not read redirections, so `cat a.md > b` passes as `head a.md > b` always has.
- **A cancellation that carries its reason is a cancellation (288).** A failed Task whose result is `cancelled: <reason>` was read as failed and stayed 🚧 in the brief, while the merge close of 283 read it as cancelled. One predicate reads the word now, and the snapshot hands every view the bare `cancelled`.
- **Records: the release smoke on installed 0.1.10 (287).** `docs/smoke-run.md` has the run: items 6 and 8 and the real panel's PC 부하 rows pass, item 5's line and item 3 fail in part (fixed by 282 and 283). Switch condition I2 has the four version cells, and M3 says what the 0.1.11 release smoke measures again.
- **The panel's header keeps only the refresh button (294).** The terminal icon and the more menu (`sangsoe todo`, `doctor` and `models` in a terminal) are gone, with everything behind them: the `panel.open` request, the worker's `orca terminal create` call, the core's read of an item's worktree, and the two error lines for a failed open. The CLI still has all four commands. When the panel cannot open or run the core it already shows one red line that names `sangsoe doctor`; a doctor reading inside the panel is left for later, since doctor runs several CLIs and downloads two trees. The Orca plugin's files change, so the plugin is approved again.
- **A session that has only finished its turn is no longer the owner's to-do (293).** Claude Code sends an `idle_prompt` notification about a minute after any turn ends, and sangsoe recorded it as `waiting_human`: all 50 such rows in one real store were idle notices. Only a permission prompt or an elicitation dialog opens a wait now; with no type in the hook input, only the permission wording does. Whether the installed Claude Code sends the type was not measured, so both shapes are tested.
- **Smaller reads (289 to 292, 295).** The glossary, the design page and the dashboard mock have the 👀 리뷰만 있음 row, and the `item_status` view row carries `reviewOnly` (289). The lineage check reads a unit's worktree with `worktree show` when `worktree list` leaves it out, as `start_unit` does (290). An emptied `watch.repos` watches nothing in the `ready` resource's overlap read instead of every repository, and so does a config file that is missing or has no readable `watch` (291). A session's later row is compared with the model of the start it began under, not of a newer start of the same Task (292). The stale-session list at the end of `sangsoe install` reads a `node` or an entry whose path holds a space (295).
- **README: a route from a pre-release to the stable release without uninstalling, marked not measured.**
- **`sangsoe item set <iNNN>` changes an existing item's lead group, hold or trigger (279).** It adds one `item_extra_set` row and touches nothing in Orca: `--lead <lead>`, `--hold true|false`, `--trigger <ISO date|owner/repo#N>`. A trigger that is neither a date nor a PR is refused. There is no MCP twin: a session that runs it passes a permission prompt, and the orchestrator hands it to a worker or the owner. With it, the brief's next column says `⏸️ 보류` for an item held by itself and `trigger 확인 필요` for one whose trigger no script reads, where both said `선행 대기`; `sangsoe migrate` gives an imported item the lead group of an old `who` of `lead:<name>` (items already imported are moved with `item set`); and a PR trigger spelled with capitals (`Owner/Repo#12`) is read as a PR.

### Changes

- **A refused act stops, is reported once, and the lead or orchestrator decides, in sangsoe's own skills (255).** The full refusal rules lived only in the retired plugin, so sangsoe's refusal paragraph left out which refusals count, bundled calls, the one reword of a text-only hook block, where the command file goes, how a subagent's refusal travels and who decides. write-brief's refusal paragraph now says all of that and every subagent prompt carries it; a subagent puts the refusal in its result and the session that started it escalates it. deliver-ticket, orchestrate's refusal-report row and end-session point at the paragraph.
- **The permission rules also cover the `sangsoe` commands sessions are told to run (265 ⑦).** Decision 256 tells every role to run `sangsoe pressure wait` through Bash after a pressure refusal, and no rule covered it, so the session could meet a permission prompt on that very call. The generator now reads `sangsoe <command>` in skills and agents and in the gates' text. Read-only verbs get a rule (`pressure wait`, `brief`, `todo`, `doctor`); `install`, `uninstall`, `plugin approve`, `land` and `item new` appear in the texts and have none. A test fails when a `sangsoe` command a skill runs is not classified.

- **Re-approve.** `brew upgrade sangsoe` installs to a new Cellar folder and the Orca plugin's content changed (the vendored core: the load thresholds in `core/capacity`), so the Orca plugin waits for approval again. Record the review of the 0.1.3 build with `sangsoe review record`, then run `sangsoe plugin approve`, as the README's Update section says.
- **If you set the `capacity` key, restart sessions that call `start_unit`.** The pressure gate runs the installed CLI on each call, so it holds a start by the new thresholds and your `capacity` entries at once. `start_unit` counts free slots inside the session's MCP server, which keeps the 0.1.2 core it loaded at start and never reads that key. On the defaults nothing differs, because the gate already holds a start at 20 GB of free disk. With a looser entry the gate lets the start through, and a session that was running during the upgrade still reports no free slot at 20 GB or less until it is restarted.
- No doctor row changes.

### Changes

- **A machine with more than 20 GB of free disk no longer holds every start.** The disk thresholds drop from warn 50 / danger 20 GB to warn 20 / danger 10 GB, so a low-load Mac with about 38 GB free starts a worker again. A start is still held at `warn` (210).
- **Load thresholds are an optional setting.** The `capacity` key of `~/.config/sangsoe/config.json` overrides `load_per_cpu`, `mem_free_pct` and `disk_free_gb` per metric, each `[warn, danger]`; a missing or malformed entry keeps the default. No sangsoe command writes the key (210).
- **The pressure gate names what binds.** Each reason gives the metric, its value and the threshold it crossed, worst first, for example `디스크 여유 8 GB ≤ 위험 10 GB`. The resource monitor's `pressure_high` reason reads the same (210).

## 0.1.2

Everything since `v0.1.1`: decisions 208–209.

### Upgrading from 0.1.1

- **Re-approve.** `brew upgrade sangsoe` installs to a new Cellar folder and the Orca plugin's content changed (the vendored core: `start_unit`, the model catalog, install), so the Orca plugin waits for approval again. Record the review of the 0.1.2 build with `sangsoe review record`, then run `sangsoe plugin approve`, as the README's Update section says.
- **Open new Claude Code sessions.** A session keeps the hooks it loaded at start: one that was running during the upgrade still runs the 0.1.1 `PreToolUse` hook with `onFailure: "block"` until it is restarted.
- No doctor row changes.

### Changes

- **Removing or upgrading no longer freezes running sessions.** The `PreToolUse` hook no longer sets `onFailure: "block"`. A hook that cannot start because `brew uninstall` or `brew upgrade` removed the plugin folder, or that finds no `sangsoe` at all, lets the call go ahead with a hook error. A gate check that runs and fails still holds the call: the hook script turns any failure of the CLI it found into exit 2. A hook that runs past its 15-second timeout now lets the call go ahead too, so the gate waits at most 500 ms for a locked store instead of 5 seconds (208).
- **`sangsoe uninstall` removes the marketplace.** It no longer passes `--scope user`, which failed when Claude Code kept the marketplace only in the profile's known marketplaces, and a removal that leaves no marketplace counts as done. Uninstall now prints that running Claude Code sessions need a restart (208).
- **`start_unit` starts a class `mechanical` worker again.** Orca's worker-start refuses any `--effort` for the fast tier's model, so `start_unit` now passes an effort only when Orca takes it for that tier's model (`orcaEfforts` in the model catalog, read from Orca 1.4.250's launch check) and says so in the start's notes. The test Orca refuses the same pairs real Orca does (209).
